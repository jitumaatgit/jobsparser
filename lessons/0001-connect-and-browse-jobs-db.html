Lesson 1 · Neovim + vim-dadbod

Browse jobs.db from inside Neovim

Connect the dadbod-ui drawer to your job database and read every row — no browser, no CLI.

Today's one win Run :DBUI, drill jobsparser → Tables → jobs → List, and see all 302 rows as a grid — without leaving the editor.

The three pieces

dadbod is two plugins and one idea.

  • vim-dadbod is the engine: given a connection it runs SQL and hands back results. (:help dadbod)
  • vim-dadbod-ui is the drawer: a navigable pane over that engine. (:help vim-dadbod-ui)
  • A connection is a named URL to a database. Yours already exists: jobsparser → sqlite:/home/mint/projects/jobsparser-fork/data/jobs.db, defined in ~/.config/nvim/lua/plugins/jobsparser-db.lua via vim.g.dbs. (:help vim-dadbod-ui-connections-g:dbs)

dadbod's sqlite adapter shells out to the sqlite3 command-line program, so that binary must be on your PATH. Yours is 3.45.1. (SQLite CLI, :help dadbod-sqlite)

[ dadbod-ui ] → [ dadbod ] → [ sqlite3 ] → data/jobs.db

Left to right: the drawer (dadbod-ui) asks the engine (dadbod), which runs the sqlite3 binary to read the file.

What your drawer actually shows

This is the real tree for your database (captured by driving :DBUI against data/jobs.db). A closed connection, then the same connection opened:

▸ jobsparser                          # closed — what :DBUI shows first

▾ jobsparser ✓                        # after you open it (✓ = connected)
  + New query
  ▸ Saved queries (0)
  ▸ Tables (7)

Open Tables (7) and you get the seven tables; open the jobs table and it expands to its helpers — predefined queries:

▾ Tables (7)
    ▾ jobs
        ~ List
        ~ Columns
        ~ Primary Keys
        ~ Indexes
        ~ Foreign Keys
    ▸ jobs_fts
    ▸ jobs_fts_config
    ▸ … (jobs_fts_content, jobs_fts_data, jobs_fts_docsize, jobs_fts_idx)

Do it — in Neovim, now

This is the feedback loop: the proof is the grid you see at the end.

  1. Run :DBUI. A drawer opens on the left with one line: ▸ jobsparser. (Plugins are lazy-loaded — the first :DBUI loads them.)
  2. Put the cursor on jobsparser and press o (or Enter). It connects (✓) and reveals New query, Saved queries (0), Tables (7).
  3. Move to Tables (7), press o. The table names appear.
  4. Move to jobs, press o. The helpers (List, Columns, …) appear.
  5. Move to List, press o. A SQL buffer opens, pre-filled with SELECT * from "jobs" LIMIT 200;.
  6. Type :w and press Enter. The query runs and a .dbout buffer renders the grid — all 302 rows.
  7. Press q in the drawer to close it (or :DBUIToggle).

Keys worth memorising now

KeyWhereDoes
o / Enterdraweropen or toggle a node
Sdraweropen the node in a vertical split
:wSQL buffersave & run the query
<Leader>SSQL bufferrun without saving (whole buffer, or a visual selection)
qdrawerclose the drawer
?drawershow every drawer mapping

Source: :help vim-dadbod-ui-mappings, :help <Plug>(DBUI_ExecuteQuery).

The gotcha everyone hits Opening a table helper by default does not run the query — it only pre-fills the SQL buffer. Auto-executing helpers is off (g:db_ui_auto_execute_table_helpers = 0). You run it by saving the buffer (:w), because g:db_ui_execute_on_save = 1. (:help g:db_ui_auto_execute_table_helpers, :help g:db_ui_execute_on_save)

If something's off

  • ✕ instead of ✓ on the connection → the file path is wrong or sqlite3 isn't on PATH. Check with which sqlite3.
  • Numbers differ — e.g. Tables (8) — a table was added since this lesson; that's fine.
  • Drawer is empty or :DBUI says nothing loaded → the plugins are lazy; make sure you ran :DBUI in the current session.
